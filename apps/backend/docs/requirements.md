# バックエンド要件定義: Lopus

## 1. システム化（開発）の目的
全国の大学生が、所属大学の枠を超えて「今ココ」の情報を共有できる、24時間限定の位置情報共有プラットフォームを構築する。大学認証により「現役学生であること」を担保しつつ、シームレスな体験を提供する。

## 2. 業務要件
- **学生認証の必須化:** 大学発行メールアドレス（.ac.jp等）による認証を行い、アカウントを作成する。
- **プロフィールの分離:** 認証用の「アカウント」と、表示用の「プロフィール」を分け、プロフィールに所属大学属性を付与する。
- **全大学共通マップ:** 全ユーザーが同一の地図空間上で情報を共有・閲覧できること。
- **情報の動的ライフサイクル管理:** 投稿から24時間を経過した情報は、自動的に参照対象から除外されること。

## 3. 機能要件
### 3.1 外部機能（APIインタフェース）
- **認証・アカウントAPI:**
  - メアド・パスワード認証、Email検証（ドメインチェック含む）。
  - アカウント管理（ロール設定含む）。
- **プロフィールAPI:**
  - ユーザー名、アイコンURL、所属大学IDの管理。
- **エフェメラル・ピンAPI:**
  - ピンの投稿（プロフィールに紐付け）、動的タグ管理、空間検索。

### 5.1 方式
- **データ構造:** 
  - `accounts` テーブル: 認証情報、ロールを保持。
  - `profiles` テーブル: ユーザー名、大学ID等を保持。`account_id` で紐付け。
  - `universities` テーブル: 大学マスター。
